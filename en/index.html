Profiles, artifact inspection and OTA install files — the last checks before you ship, in one app.

Open an IPA, APK or AAB and see what the store will show, how it is signed and what it asks for. Keep provisioning profiles in order with their expiry dates. Generate OTA install pages for test builds. Your files never leave your Mac.

Profiles

Provisioning profiles, from expiry dates to device registration

See every profile Xcode has installed at a glance. Add an App Store Connect API key and you can download, create and renew profiles without leaving the app.

Installed profiles

  • D-N expiry badges on every row — orange within 30 days, red once expired
  • Filters: All · New · Duplicates / Valid · Expiring soon · Expired
  • Detail view: device UDIDs, embedded certificates (SHA-1 · SHA-256) and entitlements, each copyable
  • Compare two profiles side by side — devices, certificates and entitlements that differ
  • Drag .mobileprovision files in to add them; multi-select to delete

App Store Connect API

  • Fetch your team's profiles and install only the missing ones
  • List registered devices and register new ones, with per-type limits shown (e.g. iPhone 3 / 100)
  • Create a profile: type, platform, bundle ID, certificates, devices
  • Regenerate or renew when devices change or expiry is near

Only an Issuer ID, Key ID and .p8 file are used. The key stays on your Mac; request tokens are signed locally.

History

  • Downloads, creations, regenerations, device registrations, additions and deletions, grouped by date
  • Search by name, bundle ID, UUID or UDID
  • Handy when you need to trace what changed and when

Artifact inspection

Open the IPA, APK or AAB before you upload it

Drop a file and it is parsed on the spot — no external tools. From store listing details to signing, permissions and security settings, every item comes with a plain-language explanation.

Store listing

The values from your product page that can be read straight out of the artifact.

  • Icon, name, provider, size, supported languages
  • iOS: category, compatibility, App Tracking Transparency prompt, privacy manifest summary
  • Android: download size, required Android version, permission count, in-app billing, advertising ID, supported devices

iOS signing and permissions

  • Signing, provisioning profile and entitlements
  • Permission usage descriptions (…UsageDescription) — warns when one is empty
  • Frameworks, app extensions and entitlement lists shown in full, never truncated

Android signing, security and 16 KB

  • Certificate fingerprints SHA-256 · SHA-1 · MD5 and key hashes for Kakao and Facebook
  • Permission classification and device features
  • Manifest security settings: allowBackup, cleartext HTTP, exported components, deep links
  • 16 KB page-size alignment check for native libraries
  • Build, configuration and size breakdown (DEX, resources, native libs per ABI)

Read-only. The file is never modified, nothing is written next to it, and nothing is uploaded anywhere.

OTA distribution

Install test builds from a single link

Turn an existing IPA or APK into an install page and a QR code. Upload the files to your own https server and you are done.

iOS — Ad Hoc · Enterprise

  • manifest.plist, install.html and a QR code for the itms-services:// install link
  • Bundle ID, version, build and app name are filled in from the IPA
  • Release notes you type go straight into the install page

Android — APK

  • install.html with icon, version, SHA-256, install guide and changelog
  • A QR code pointing at the install page
  • Package, version, app name and icon are filled in from the APK

You host it

  • Pick an output folder and the files are written there
  • The app uploads nothing — put the files on your team's https server
  • iOS requires https and the link must be opened in Safari on the device
